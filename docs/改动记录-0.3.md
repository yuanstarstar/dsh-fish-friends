## 接口依据（都从源码看过）

- 插槽：`main` 是 keyed/root；侧栏入口 `sidebar.panellist` 的 `id` 必须等于 `main` 的 `key`；切换 `ctx.layout.selectPanel(id)`，`null` 回会话。参考 `dsh-client-ui-plugin-manager\lib\client.js:4451-4528`。
- 会话：`sessionController.list/prompt/create`（`dsh-api-session-controller`），标题在 `sessionQuery.readTitle`；**prompt 对冷会话会先 resume**（`lib/index.js:221-245`、`925`）。
- 切换 UI：`uiWorkspace.openSession`（`dsh-client-ui-workspace\lib\client.js:1470`）；host **没有**切换能力，所以用队列 + 浮层补齐。
- HTTP：`ctx.effect(() => ctx.webServer.register({kind:'prefix', path, handler}), label)`，无鉴权只对本机 GUI（外部 curl 403）。

## 0.3.1 修复（真机暴露的坑）

装进 profile 后第一次真机调用 `friends_session {list:true}` 报：
`cannot get property "lifetime" without inject`。

原因：host 插件作用域里 `ctx.lifetime` 是要声明 inject 的服务属性，没声明就抛；
而 subagent 文档里的 `ctx.lifetime.signal` 是 DSH 内部（会话控制器自己）的写法。

修法：`lib/session.js` 新增 `signalOf(ctx)`：
先 `try { ctx?.lifetime?.signal }`，拿不到就退回一个按 ctx 缓存的、永不 abort 的 `AbortController.signal`；
`session.js` / `tools.js` / `http.js` 里 4 处调用全部改用它。
回归：`test/signal.mjs`（用会抛错的 getter 模拟宿主）全过；v2 18/18、v3 24/24、smoke 17/17。

> 改 host 代码必须重启 DSH 才生效（client.js 刷新即可，host 不会热更）。
