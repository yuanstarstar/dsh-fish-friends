# 改动记录 · 0.4.0（桥接 + 自动建档 + 专属会话 + 限流 + 主动闲聊）

## 这一版要解决的

用户原话要点：

1. 机器人监听**不同桥接、不同人**的消息（桥接让机器人自己做好），并通过桥把话发回去。
2. 这些消息先进同一个会话（总台）。
3. 同一个人第 **3** 次发消息时：**自动建档**，并在「专属朋友工作区」建一个**专属会话**专门接听；原总台会话不再接他的消息。
4. 专属会话可设**一定时间内上限**（限流）。
5. 也可设「主动闲着无聊来找它聊天」：可设**时间段**，并按**亲密度决定频率**。

## 0.4.1 修复：file 桥重复收到同一条消息

**症状**：file 桥里追加一条消息，机器人会反复「收到」它（每秒一次），会话里出现重复内容。

**根因**（`lib/bridge.js` 的 `drainFileBridge`）：读取游标 `offset` 按**字节**记账（`Buffer.byteLength`），但切片用的是**字符串下标**（`text.slice(st.offset)`、`text.length`）。
JSON 行里只要有一个中文/emoji，字节数就大于字符数，于是 `text.length < st.offset` 永远成立 → 每次轮询都判定「文件被截断」→ 游标归零 → 整个文件重读一遍 → 同一行被重复投递。

**修法**：整个读取链路改成按 Buffer 走字节。
- `fs.readFileSync(file)` 不再带 `'utf8'`，直接拿 Buffer；
- 游标 `offset` 用字节推进：`st.offset += end + 1`（`end` 是 `chunk.lastIndexOf(0x0a)` 的字节下标）；
- 拼半行用 `Buffer.concat`，`partial` 存 Buffer；
- 只在**结尾换行**之后推进游标，半行既不吞也不重；
- 解析时才 `complete.toString('utf8')`。

顺带：
- 新增 `resetFileCursor(bridgeId)`（删桥/测试时清游标）；
- `test/dup.mjs` 覆盖 6 种情形：空文件、中文两行只读一次、追加 emoji、半行等换行、文件截断重读、运行时轮询端到端只 ingest 一次。

**验证**：`test/dup.mjs` 6/6；全量回归 v2 18/18、v3 24/24、v4 23/23、signal 全过、smoke-host 全过。

## 0.4.2 修复：新会话不认识对面是谁 + 同一个人被重复建档

### A. 新会话的交接记忆

**症状**：给某个朋友新建/换绑一个会话后，进去的模型不知道对面是谁（新会话不继承旧会话的记忆），常常重新自我介绍、问「你是谁」，甚至把交接说明当成对方发来的消息回一句。

**修法**：新增 `lib/briefing.js`，把「TA 是谁、聊过什么、怎么回话」拼成一段交接记忆，投进该朋友绑定的会话：

- `buildBriefing(friend, db, {bridgeName, reason, samples})` 生成文本：首行声明「这是系统提示不是 TA 说的话、不要回复这条、也不要为这条调用 friends_send」，然后分节写对方是谁（名字/通道+uid/别名/亲密度/互动次数/爱好/印象）、来历（自动建档 / 换的新会话 / 手动绑定 / 第一次）、最近聊过什么（末 8 条收发 + 建档前攒的几句）、怎么回。
- **和 TA 的第一条真实消息拼成一次投递**（`prepareBriefing` 只组装、不投；`deliver` 拼 `交接文本 + 「—— 下面这条才是 TA 刚发来的消息 ——」 + 【桥名】原话`），避免单独一投让模型对交接说明回一句。
- 同一会话只交接一次：`friend.briefed = { sessionRef, at }`（`markBriefed`），`normalizeFriend` 会保留该字段；`sessionRef` 变了 = 换绑/重建 → 措辞自动变「换的新会话」并重新交接。
- 交接投失败（如 `session/agent-busy`）不挡消息：自动退一步只投消息，备注写「交接记忆没送到（原因）」。
- 入口：`briefIfNeeded`（建档首次、换绑、激活前、限流补投前）、`resendBriefing`（`friends_session {rebrief:true}` 强制重发）；`friends_activate`、`friends_session` 绑定、`POST /session` 绑定都会顺手交接。

### B. 同一个人可能被重复建档

**症状**：同一个人连发几条，或两条消息刚好一起跨过建档阈值时，鱼友簿里出现**两份同名档案**（各自绑了一个专属会话）。

**根因**：旧 `promote` 是「先建会话、再 mutate push friend」；从判定「该建档」到写库之间隔着异步的 `createSession`，这期间后来的消息再次判定阈值已满，又走一遍 promote。

**修法**（`lib/routing.js`）：

1. `promote` 改成**原子占位**：一次 `mutate` 里先 `findFriendBySender` 查重，已存在就直接复用（并清 pending），否则 push 占位 friend（`session:null`）并清 pending；之后才建工作区/会话，最后把 `session.ref` 补写回去。同进程并发两次 promote 只会建一份档案、一个会话。
2. `ingestIncoming` 对同一个 `bridgeId:uid` **串行**（模块级 `ingestChains` Promise 链），连发不会交错。
3. `pendingSenders` 增加 `promoting` 时间戳（`normalizePending` 保留）：建档进行中再来的消息走「暂存」分支，进 `holds` 且 `reason:"promoting"`，不再触发第二次建档；`releaseHolds` 会按 `bridgeId+uid` 找回这个人并补投到专属会话（会话没建好就留着下次再试，不丢）。
4. `releaseHolds` 顺带修了一个丢消息点：以前「找不到 friend 或 target 为空」都会直接删 hold，现在只有在**找不到这个人**时才删。

**验证**：新增 `test/dup-promote.mjs` 5/5（并发 promote 只建一份、同人连发 5 条只建一份且第 3 条起进专属、`promoting` 期间暂存不建档、建档后补投、每人一份）；`test/brief.mjs` 8/8（拼一次投递、只交接一次、换绑重投、强制重发、交接失败不挡消息）；`test/v4.mjs` 23/23；v2 18/18、v3 24/24、signal 全过、dup 6/6、smoke-host 全过。

## 0.4.3 修复：朋友一多，面板滚不动

**症状**：鱼友簿面板里朋友/卡片变多后，下半部分被裁掉，鼠标滚轮滑不下去，看不到后面的桥接、路由、消息流、主动闲聊几块。

**根因**（`client.js` 的 `S.wrap`）：面板根节点只有 `{color, fontSize}`，是个普通 block。`main` 插槽给的容器是 `display:flex; flex-direction:column; overflow:hidden`（`dsh-client-ui-layout/lib/client.js` 的 `.centerCol`），内容超过一屏就被直接裁掉；根节点自己没有 `height`/`overflow`，所以没有滚动容器，滚轮事件没有接收者。

**修法**：让面板根节点自己成为滚动容器：

```js
wrap: {
  color: C.text, fontSize: '12px',
  boxSizing: 'border-box',
  height: '100%',        // 撑满 main 插槽给的高度
  minHeight: 0,          // flex 子项允许收缩
  overflowY: 'auto',     // 内容超长时出现滚动条
  overflowX: 'hidden',
  paddingRight: '4px',   // 给滚动条留位置，别压住卡片边框
  paddingBottom: '28px', // 最后一张卡片别贴底
  overscrollBehavior: 'contain', // 滚到底不要带动外层
}
```

写法和 DSH 自带插件面板一致（`dsh-client-ui-plugin-manager` 的 `.page` 就是 `height:100%; overflow:auto`，见其 `lib/client.js:1919`），所以不依赖额外的 CSS 文件或插槽参数。

**验证**：`node --check client.js` 通过；`test/smoke-host.mjs` 全过（插槽装配 + 四个区块渲染）；`test/v4.mjs` 23/23。滚动是纯样式行为，真机验收见下。
