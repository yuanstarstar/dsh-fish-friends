# dsh-fish-friends 0.1.0 研究笔记

> 结论先放前面：**接口写法是对的，能跑；但逻辑层有 3 个会崩/会丢数据的坑、3 个打分反直觉的地方，README 有 4 处和代码对不上。**
> 想改之前建议先把「数据层」加固，否则你加的功能越顺手，越容易把 `friends.json` 写坏。
>
> 研究方式：不需要 DSH，用假 ctx 把 `lib/tools.js` 直接跑起来（见 `test/`），下面所有数字都是实测输出，不是读代码猜的。

---

## 1. 它是什么

一个纯本地的小本子：记「鱼友」是谁、在哪个平台、爱看什么、多久没说话，然后按内容算「这条东西该发给谁」。

```
模型调用 friends_* 工具
        │
        ▼
lib/tools.js  registerTools(ctx)  ← 7 个工具
        │  读改写
        ▼
$DSH_HOME/fish-friends/friends.json   （本机 = %USERPROFILE%\.dsh\fish-friends\friends.json）
```

- 不联网、不读宿主日志、不注入 UI。唯一副作用是那一个 JSON 文件。
- 全量读写：每次调用都是「整个文件读进来 → 改内存 → 整个文件写回去」，没有增量写、没有锁。

### 7 个工具

| 工具 | 作用 | 行号 |
| --- | --- | --- |
| `friends_upsert` | 建/改档案（名字、平台、uid、爱好、通道、印象、别名） | `lib/tools.js:98-145` |
| `friends_note` | 记一次互动，顺带刷「上次说话」 | `lib/tools.js:147-168` |
| `friends_list` | 列表（name/recent/stale/close 四种排序） | `lib/tools.js:170-190` |
| `friends_due` | 超过 N 天没说话的（默认 7） | `lib/tools.js:192-203` |
| `friends_show` | 单人档案 + 最近 10 条互动 | `lib/tools.js:205-223` |
| `friends_match` | 一条内容 → 谁最合适 + 理由 + 怎么发 | `lib/tools.js:225-248` |
| `friends_share` | 登记「分享给谁」，可自动挑人 | `lib/tools.js:250-280` |

## 3. 数据模型

`friends.json` 实际长这样（实测落盘）：

```json
{
  "settings": { "shareLimit": 1 },
  "friends": [
    {
      "name": "阿蓝",
      "createdAt": 1794758344065,
      "updatedAt": 1794758344065,
      "platform": "bilibili",
      "uid": "1001",
      "interests": ["大肥鱼", "龙珠"],
      "channels": [{ "platform": "bilibili", "uid": "1001", "kind": "私信" }],
      "impression": "喜欢看整活",
      "aliases": ["蓝哥"],
      "lastTalkAt": 1794758390000,
      "log": [
        { "at": 1794758390000, "kind": "talk", "text": "聊了新视频", "mood": "顺" },
        { "at": 1794758399000, "kind": "share", "text": "龙珠手办", "sent": true }
      ]
    }
  ]
}
```

### 字段来源

| 字段 | 谁写 | 备注 |
| --- | --- | --- |
| `name` / `interests` / `channels` / `impression` / `aliases` | `friends_upsert` | 爱好/别名/通道都是**并集**追加，无法用工具删掉单项 |
| `platform` / `uid` | `friends_upsert` 的旧字段 | 只在 `channels` 不是数组时，`load()` 才会用它合成通道（`lib/tools.js:25-27`） |
| `log[]` | `friends_note` / `friends_share` | 每人**只留最近 80 条**（`.slice(-80)`），两类混在一起 |
| `lastTalkAt` | `friends_note`；`friends_share` 且 `sent:true` | |
| `settings.shareLimit` | 手改文件 | 代码只在「不是数字」时补 1（`lib/tools.js:22`），所以手改成 3 会生效（实测 limit=2 时真的出两个人） |

### 亲密度公式（`affinity`，`lib/tools.js:50-57`）

```
亲密度 = clamp(20 + min(55, 互动次数×8) + max(0, 40 − 断联天数×2) + 分享次数×2, 0, 100)
```

实测（1 次互动、无分享）：

| 断联天数 | 0 | 10 | 19 | 20 | 21 | 40 |
| --- | --- | --- | --- | --- | --- | --- |
| 亲密度 | 68 | 48 | 30 | 28 | 28 | 28 |

两个结论：
1. **断联衰减 20 天就掉光了**，不是 README 说的 40 天（`40 - d*2` 在 d=20 时归零）。
2. 掉光之后还有 **保底 20 + 互动分**，所以半年不联系的老熟人仍显示 28，README 里「不会还显示很亲」的说法偏乐观。

## 6. 问题清单

### P0（会崩、会丢数据，改功能前先修）

**P0-1 `friends.json` 里只要有一条脏数据，部分工具直接抛异常**
- 实测：`friends:[null]` → `friends_list` 抛 `TypeError: Cannot read properties of null (reading 'interests')`（`load()` 的归一化循环 `lib/tools.js:23-29` 在 `try` 外面）。
- 实测：条目缺 `name` → `friends_note` / `friends_show` 抛 `TypeError: ... (reading 'toLowerCase')`（`find()`，`lib/tools.js:43-45`）；`friends_list` 显示成 `undefined｜亲密 20`；`sort:'name'` 抛 `... (reading 'localeCompare')`。
- 触发方式很日常：手改文件、旧版本字段名、脚本导入。
- 修法：`load()` 里过滤 `!f || typeof f.name !== 'string' || !f.name.trim()` 的条目（或补名 `未命名-<createdAt>`），并把归一化搬进 `try`。

**P0-2 JSON 坏了会被「静默清空」，下一次写把旧数据真覆盖掉**
- 实测：把文件写成非法 JSON → `friends_list` 回「鱼友簿还是空的」→ `friends_upsert` 成功之后，文件里**原来的内容全没了**，只剩下新写的那一条（探针里故意把「这不是合法 JSON…」写进文件，覆盖后原文一个字都不剩）。
- 根因：`load()` 的 `catch {}` 什么都不说（`lib/tools.js:18-20`），`save()` 直接整文件覆盖（`lib/tools.js:33-36`）。
- 顺带：文件带 UTF-8 BOM 也会走到这个分支（`JSON.parse` 吃 BOM 报错）。
- 修法：`catch` 里把原文件重命名成 `friends.corrupt-<ts>.json` 再继续；或直接抛错让工具失败，不要静默返回空库。

**P0-3 模糊匹配会把新朋友并进老档案**
- 实测：已有「阿蓝」，`friends_upsert({name:'蓝'})` → 回执「更新了：阿蓝」，爱好被合进阿蓝，**没有新建**。
- 根因：`find()` 三级降级里最后一级是子串包含（`lib/tools.js:45`）。`friends_upsert`、`friends_note`、`friends_share` 全走它。
- 影响：名字短的（「蓝」「鱼」「哥」）、英文名大小写、别名相近的人，都会被静默合并。
- 修法：写操作只用精确名/别名；模糊匹配留给 `show`/`note` 且回执里明说「匹配到 X，是否指它」。

### P1（不崩，但结论反直觉）

**P1-1 匹配分没有上限，爱好越多越占便宜**
- 每个命中的爱好 +30，可叠加（`lib/tools.js:74-76`）。实测同一句话：6 个爱好的人拿 **218 分**，只爱一个且有命中的人拿 **40 分**（差距 5.5 倍，纯粹是爱好条数堆出来的）。
- 修法：`score` 封顶 100，或每命中一次递减（30/20/12），或改成「爱好命中数 / 爱好总数」的比例分。

**P1-2 亲近程度压过主题相关**
- 实测：内容是「一个塔防攻略」。塔防党（唯一爱好=塔防，断联 20 天）拿 40 分；一个从没提过塔防、但最近天天聊天的人拿 58 分 → **工具推荐了后者**。
- 根因：`score = affinity/2`（最多 50）+ 爱好 30 + 最近聊天 8（`lib/tools.js:73,81-83`）。亲密差距可以轻易吃掉一个爱好命中。
- 修法：爱好命中的权重提到 40~45，或先按「兴趣命中」筛人、再按亲密度排序。

**P1-3 没发出去的分享也算亲密度**
- 实测：`friends_share({sent:false})` 后亲密度 20→22。`shared` 统计只看 `kind==='share'`，不看 `sent`（`lib/tools.js:55`）。
- README 写的是「分享过几次，每次 +2」，语义上应该只算已发。
- 修法：`filter(l => l.kind==='share' && l.sent)`。

### P2（不影响功能，但会坑后面改的人）

| # | 现象 | 位置 |
| --- | --- | --- |
| P2-1 | **顶层字段会被吞**：`friends.json` 里加 `shares:[...]`，任何一次写之后只剩 `friends`/`settings` | `load()` `lib/tools.js:15-31` 白名单式重建 |
| P2-2 | 数据没有 `version` 字段，将来改结构没有迁移入口 | 同上 |
| P2-3 | 每人 log 只留 80 条，90 次互动后第 0~9 句被挤掉（实测首条变「第10句」） | `.slice(-80)` 出现 3 处 |
| P2-4 | 没有锁：两个会话同时写，后写覆盖先写（本机单进程下暂未观测到丢失） | `save()` |
| P2-5 | 代码里 4 处「她」硬编码性别（`lib/tools.js:75,79,107,155` 及 README 多处） | — |
| P2-6 | 亲密度只算「最近 80 条」里的互动，但 base 封顶 55，实际无影响（可忽略） | `affinity()` |
| P2-7 | `friends_list` 每次都多印一行 shareLimit 提示，模型上下文里纯噪音 | `lib/tools.js:187` |

### 文档与实现不符（README 要同步）

1. 「每天 −2，**40 天**掉光」→ 实际 **20 天**掉光（`40 - d*2`）。
2. 公式漏了 **+20 基础分**，所以「半年不联系不会还显示很亲」不成立（实测保底 28）。
3. 安装步骤说「把目录放到 `~/.dsh/plugins/...`」，但本机 `~/.dsh/plugins` 是空的，现有插件全是 `link:` 指向开发目录 —— 两种都行，但按本机习惯链接更省事（见第 8 节）。
4. 没说数据文件位置/结构，也没说 log 只留 80 条。

## 7. 要改的话，改哪里

| 你想做的事 | 动哪 | 注意 |
| --- | --- | --- |
| 调亲密度公式 | `affinity()` `lib/tools.js:50-57` | 改完同步 README 第 38-46 行；用 `edge.mjs` 的 B 组验边界 |
| 调「给谁」的权重 | `matchScore()` `lib/tools.js:70-86` | 三个信号：`affinity/2`、每爱好 +30、最近聊天 +8；`reasons` 是给模型看的解释，改权重别忘了改话术 |
| 加一个字段（如 `birthday`、`group`） | `load()` 归一化 `:23-29` + `friends_upsert` 参数 `:101-120` + 回执 `brief()` `:59-65` | 三处都加，否则字段会「写进去但看不见」 |
| 加一个新工具 | 在 `registerTools()` 里再 `register({...}, 'label')` | 模板：`name/description/parameters/execute`，`output` 可省略（`register` 会自动补 `TEXT_OUTPUT`，`:93-96`） |
| 加一个全局设置 | `settings` 对象 + `load()` 默认值 `:22` | 现在只有 `shareLimit` 一个先例；注意 `load()` 白名单会丢非 `settings` 的顶层键 |
| 删除/归档鱼友 | 新增 `friends_forget` | `load()` 目前把 `friends` 规范化后整体写回，删元素 = 过滤后 `save()` |
| 导入导出 | 新增两个工具，直接读写 `friends.json` | 导入前先按 P0-1 校验，不然一条脏数据能永久毒化库 |
| 让它出现在设置界面 / 加卡片 | `package.json` 加 `exports`，补 `export const Config`（schemastery）或 `client.js` | 属于「升级成 UI 插件」，比改工具复杂一个量级；参考 `dsh-meituan`/`dsh-scribble` |
| 真把内容发出去 | 本机已有发送类工具（`df_live_send` 弹幕、`dafeiyu_mod_say` 弹幕），**没有私信工具** | 别在插件里自己搞登录；让模型串工具调用，本插件只管登记 |

新工具最小骨架（粘进去改）：

```js
register({
  name: 'friends_forget',
  description: '从鱼友簿里删掉一个人（软删：加 archivedAt，不再参与匹配）。',
  parameters: { type: 'object', properties: { name: { type: 'string' } }, required: ['name'] },
  execute: async ({ name } = {}) => {
    const db = load()
    const f = find(db, name)
    if (!f) return { text: `❌ 没有「${name}」` }
    f.archivedAt = now()
    save(db)
    return { text: `已归档：${f.name}` }
  },
}, 'fish-friends:forget')
```

## 9. 建议的改造顺序

1. **0.2 数据层加固**（P0-1/2/3 + P2-1 + `version` 字段）：不加新功能，只让库写不坏。约 60 行改动，收益最大。

3. **0.3 功能**：删除/归档、导入导出、分享历史回看（`friends_show` 里分开展示 talk/share）。
4. **0.4 才考虑 UI/打通**：`Config` + 设置界面，或接 `df_live_send` 做「真发」。

前两步做完再动功能，比先加功能回头补数据层省事得多。
